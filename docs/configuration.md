# Configuration reference

The namespaced `Repository` API is `backup.cnpg-backup.djosh34.github.io/v1alpha1`. Its schema is [config/repository-crd.json](../config/repository-crd.json), generated by [hack/repository_crd.py](../hack/repository_crd.py). Runtime defaults and validation are in [internal/configuration/repository.go](../internal/configuration/repository.go). Generated ConfigMaps are configuration projections and status, not editable alternatives to the Repository or Cluster.

[operations.md](operations.md) gives installation and recovery procedures. The examples contain placeholder storage settings, not a ready-to-apply installation.

## Repository identity and storage

| `spec` field | Accepted value or default |
|---|---|
| `repositoryID` | Required lowercase, nonzero UUID identifying one lineage |
| `s3.endpoint` | Required HTTPS authority, without credentials, query, or path other than `/` |
| `s3.bucket` | Required DNS-compatible bucket name, 3 to 63 characters |
| `s3.prefix` | Required normalized relative path, 1 to 128 printable ASCII bytes. No empty, `.` or `..` segments, backslash, `%`, `?`, or `#` |
| `s3.signature` | `v4` by default, or `v2` |
| `s3.addressing` | `path` only |
| `s3.region` | `us-east-1` by default, explicit nonempty value up to 64 characters |
| `s3.accessKeySecret`, `s3.secretKeySecret` | Required `{name,key}` selectors in the Repository namespace |
| `s3.sessionTokenSecret` | Optional `{name,key}`, V4 only |
| `s3.caConfigMap` | Optional `{name,key}` selecting an additional PEM CA bundle in the same namespace |
| `s3.encryption` | `bucket-default` only. The plugin does not configure bucket encryption or send per-object SSE options |
| `compression` | `gzip` by default, fixed level 1, or `none` |

`repositoryID`, endpoint, bucket, prefix, signature, addressing, and region are immutable. Credential and CA selectors can change. The runtime uses explicit credentials, never an ambient chain. TLS verification is mandatory. Proxies, redirects, signer fallback, and V2 session tokens are unsupported. V2 on AWS endpoints is rejected because the SDK would override it with V4.

A repository has one writer Cluster UID. A restored writer needs a distinct destination UUID, even when the source and target PostgreSQL system identifiers match. A local source Repository can point to storage whose original Kubernetes objects no longer exist. See [permissions and backend requirements](repository.md#storage-requirements).

## I/O controls

Durations use Go duration syntax, such as `336h`, not `14d`. Shorter caller deadlines take precedence. A deadline never expires deletion protection.

| `spec.io` field | Default | Accepted range |
|---|---:|---:|
| `connectTimeout` | `10s` | `1s` to `1m` |
| `metadataTimeout` | `30s` | `1s` to `2m` |
| `dataRequestTimeout` | `15m` | `10s` to `1h` |
| `operationTimeout` | `24h` | `1m` to `168h` |
| `walUploadTimeout` | `120s` | `10s` to `15m` |
| `artifactUploads` | 2 | 1 to 2 |
| `partWorkers` | 2 | 1 to 2 per artifact |
| `walUploads` | 2 | 1 to 2 |

Process-wide limits remain two artifact streams, two independent WAL transfer slots, and eight HTTP requests across overlapping configuration snapshots. Multipart parts are 64 MiB. Reads have at most five attempts. Mutations have one attempt and explicit uncertainty handling.

## Native work and capacity

| `spec` field | Default | Accepted range |
|---|---:|---:|
| `workspace.storageClassName` | None, required | StorageClass for a dedicated finite filesystem |
| `workspace.size` | `256Gi` | `1Gi` to `8Ti` |
| `native.maxBackupBytes` | 32 GiB | 1 byte to 1 TiB, raw archives plus manifest |
| `native.maxBootstrapWALBytes` | 8 GiB | 1 byte to 256 GiB, no greater than `maxBackupBytes` |
| `native.maxRestoredBytes` | 32 GiB | 1 byte to 1 TiB |
| `native.maxReferenceAge` | `192h` | `1h` to `720h` |
| `native.captureTimeout` | `6h` | `1m` to `6h` |
| `resources.requests` | CPU `100m`, memory `256Mi` | Positive CPU and memory, no greater than limits |
| `resources.limits` | CPU `2`, memory `3Gi` | Positive CPU and memory, capped at these defaults |

Byte-budget fields are JSON integers. Resource quantities and workspace size use Kubernetes quantity syntax. Extra resource types and resource claims are not supported. The cgroup limit includes native children. One native capture runs at a time per sidecar, independently of WAL service.

Each Pod or Job gets its own generic ephemeral workspace PVC. The runtime requires dedicated writable ext4 or xfs filesystem roots whose actual capacity does not exceed the declared ceiling. A PVC request alone is not proof. Directory binds into a larger local-path filesystem, subpaths, shared devices, NFS, tmpfs, and `emptyDir.sizeLimit` are not supported database workspaces. Target PGDATA, WAL, and tablespace filesystems receive the same identity and capacity checks.

Capture reserves raw archives, compressed spool, remote readback, extracted WAL, file metadata, concurrent WAL work, and free-space margin. The reservation uses these byte quantities:

```text
A = native.maxBackupBytes
W = native.maxBootstrapWALBytes
S = actual WAL segment size
C = A + max(1 GiB, ceil(A / 100))
P = A + C + W + 8192 * 100000
capture workspace = P + max(1 GiB, ceil(P / 10)) + C + 6 * (S + 1 MiB) + 16 MiB
```

The second `C` covers serial remote readback. WAL-only work reserves `6 * (S + 1 MiB) + 16 MiB` in workspace. WAL restore additionally reserves `2 * S + 16 MiB` on the physical WAL filesystem; archive does not reserve unwritten output there, so backlog can drain under source disk pressure.

Differential restore reserves both inputs, extraction, full reconstruction output, and duplicated WAL during cross-volume copy. Each target filesystem must satisfy its own reservation. In differential reconstruction, each PGDATA or tablespace filesystem conservatively reserves the entire output maximum. Source PGDATA is never scratch space. The [native implementation](../internal/postgres/restore_capacity.go) and [differential reconstruction](../internal/postgres/restore_differential.go) calculate phase-specific reservations rather than estimating them from compressed size.

Fixed input limits are 64 MiB per original manifest, 100,000 file entries, 64 tablespaces, 66 artifacts, 512 GiB per stored artifact, 1,023 bytes per native path, and 1 GiB plus 1 MiB per regular file. Increasing configuration budgets does not relax these limits or promise a particular database size or restore time.

## Retention and freshness

| `spec` field | Default | Accepted range or meaning |
|---|---|---|
| `retention.enabled` | `false` | No periodic retention until enabled |
| `retention.dryRun` | `true` | Plans without destructive execution |
| `retention.window` | None | Required when enabled, `1h` to `87600h` |
| `retention.minimumFulls` | 2 | 1 to 100, independent of window |
| `retention.interval` | `1h` | `5m` to `24h` |
| `backupFreshness.fullMaxAge` | Unset | Optional `1m` to `87600h` |
| `backupFreshness.differentialMaxAge` | Unset | Optional `1m` to `87600h` |

Freshness budgets enable per-type alerts. They do not create schedules or prove recoverability. The [example Repository](../config/repository-example.json) uses a 336-hour retention window and 192-hour full and 26-hour differential freshness budgets. Those budgets suit weekly fulls and daily differentials. Retention has no independent aggressive WAL expiry and no force-clear or holder TTL setting.

## CNPG resources

The plugin name is `cnpg-backup.djosh34.github.io`. `Cluster.spec.plugins[].parameters` contains only `repository`, selecting a destination Repository in the Cluster namespace. The WAL archiver entry sets `isWALArchiver: true`.

`Backup` and `ScheduledBackup` require `target: primary`, `method: plugin`, and `pluginConfiguration.parameters.backupType: full` or `differential`. Missing type and extra parameters fail validation. CNPG owns scheduling and Backup status. A differential references the original manifest of an eligible full and never falls back to a full.

The supported database image is the digest-pinned PostgreSQL 18.6 image in [config/cluster-example.json](../config/cluster-example.json). Its `:18.6` tag component supplies CNPG version metadata, while the digest fixes its bytes. Separate WAL storage is required. Tablespaces must be CNPG-managed with distinct normalized names and mounts. Replica-cluster bootstrap, standby capture, overlapping target writers, and `cnpg.io/skipEmptyWalArchiveCheck` are unsupported.

Actual native preflight requires primary PostgreSQL 18.6, 8 KiB blocks, 1 GiB relation segments, `full_page_writes=on`, `wal_level=replica` or `logical`, and `summarize_wal=on`. `archive_timeout` must be positive and no greater than 60 seconds. `wal_summary_keep_time` must exceed the maximum reference age plus capture timeout plus 24 hours of slack, and cannot exceed 3,650 days. PostgreSQL still checks actual summary coverage. Its `14d` example is PostgreSQL syntax, unlike Repository duration fields. A restart, promotion, or checksum-state transition requires a new explicitly requested full before another differential.

## Recovery targets

`bootstrap.recovery.source` selects an `externalClusters` entry whose plugin has a source `repository` parameter. Source and destination Repository names and UUIDs must differ. [config/recovery.py](../config/recovery.py) renders a fresh single-instance recovery Cluster.

| `recoveryTarget` value | Selection rule |
|---|---|
| `{}` | Latest usable backup and continuous known WAL through the admitted archive frontier |
| `backupID` | Exact CNPG Backup UID, not its resource name |
| `targetTime` | Timezone-qualified RFC3339. Source capture completion must be strictly earlier |
| `targetLSN` | Canonical PostgreSQL LSN. Native backup end must be strictly earlier |
| `targetName` | Requires `backupID` and a unique named restore point |
| `targetXID` | Requires `backupID`, a known top-level committed transaction, and no wrap ambiguity |
| `targetImmediate: true` | Requires `backupID`. Stops at that backup's first consistent point |
| `targetTLI` | Canonical positive decimal string, such as `"2"`. Omission resolves a unique latest descendant. `current` and `latest` are rejected |
| `exclusive` | Boolean, only for time, LSN, or XID targets |

Only one target kind is allowed. Source WAL RPC work has a 60-second budget and the helper a 75-second deadline. The credential-free recovery envelope is capped at 16 MiB. The manager retains at most 16 active observers or unacknowledged closed fences, with 1,024 Pods per observer. Exhaustion fails closed without removing source protection.

Selected backups must precede relevant timeline forks. Competing timeline leaves require an explicit numeric target. The action is `promote`. PostgreSQL must actually reach explicit targets. Download, reconstruction, or RPC success is not recovery success.

## Manager installation

[config/render.py](../config/render.py) accepts immutable `--manager-image` and `--data-image` references, `--namespace` for the operator namespace, `--managed-namespace`, and repeated `--secret-name` allowlist entries. It emits a one-replica Recreate Deployment, namespaced RBAC, cert-manager certificates, mTLS discovery on 9090, and internal HTTP metrics on 9091. Default manager resources are 50m CPU and 64 MiB requested, with limits of 500m and 256 MiB.

The Secret allowlist includes S3 credentials and the selected Cluster's replication certificate and public client/server CA Secrets. Default CNPG names are `<cluster>-replication` and `<cluster>-ca`. The manager has get-only Secret access. Sidecars receive explicit projections, never application credentials, the superuser password, or the server private key.
